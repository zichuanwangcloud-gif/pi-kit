# PRD 文件模板

> 本文件由 `generate-prd` 的 Step 3 在**写入 PRD 文件前**读取。包含 frontmatter 定义、十章正文模板与逐章填写要求。
> 从 SKILL.md 下沉至此：模板只在最后写文件那一步用得上，常驻正文会让每次访谈都白白加载 250 行。

---

**Frontmatter**：

```yaml
---
feature: "{功能名称}"
module: "{主题}"
status: "待设计"
complexity: "pending"
generated_by: "generate-prd"
generated_at: "{ISO8601}"
updated_at: "{ISO8601}"
version: "v1.0"
filename: "{域前缀}-{主题}-{功能名称}-{YYYYMMDD}-v1.0-待设计.md"
linear_issue: null
linear_url: null
linear_synced_at: null
---
```

**任务系统关联字段说明**（三个字段生成时一律填 `null`，提交到任务系统后回写，不要手填）：

| 字段 | 含义 | 回写示例 |
|------|------|---------|
| `linear_issue` | 本 PRD 对应的主 Issue identifier，一对一 | `"CR-1130"` |
| `linear_url` | Issue 直达链接 | `"https://linear.app/<workspace>/issue/TEAM-123"`（示例占位，按实际工作区与 team key 填） |
| `linear_synced_at` | 建单并回写的时间 | `"2026-08-28T14:20:00+08:00"` |

与两个既有字段**语义不同，不要混用**：`related_issue` 指相关但非本体的 Issue（如"CR-1240，本 PRD 吸收"）；`related` 指关联的其他 PRD 文件。

**内容填写规则**：
- 第 1 章（概述）：必须基于访谈信息填写实质内容，使用业务语言描述；**1.4 术语对照表在涉及 ≥3 个业务术语时为强制项**，且必须先于其他章节完成
- 第 2 章（竞品分析）：**条件包含** — 仅当执行了竞品分析时生成此章节
- 第 3 章（需求与用户故事）：必须基于访谈信息填写实质内容。使用业务语言描述需求，不得引用代码文件路径、函数名、API 端点等代码级/接口级信息
- 第 4 章（验收清单）：基于需求清单推导，填写具体验收步骤
- 第 5 章（页面 UI/UX 设计）：**条件包含** — 仅当功能涉及页面变动时生成此章节
- 第 6 章（技术约束）：**始终保留章节标题**，但默认内容为「待补充（由研发人员补充）」
- 第 7 章（排除项）：**不得留空**；未经人工确认的拓展项也记录在本章，标注「拓展项-待确认」，确认后才可移入第 3 章需求清单
- 第 8 章（影响范围）/ 第 9 章（非功能要求）：完整档强制项，无信息时先由 AI 起草、用户确认，禁止留空进对外提交
- 第 10 章（下一步）：固定内容
- **章节分层**：标注为「本地留存章节」的内容（文档说明 / 事实核实状态 / 竞品分析 / 变更记录等）在本地 PRD 中必须写全，但对外提交正文时整章剔除并重排编号，详见「全局约束：本地留存 vs 对外提交」
- **全局禁令**：PRD 文档中（除第 6 章由用户主动要求外）不得出现具体代码文件路径、函数/类名、API 端点、请求/响应结构、数据库表/字段名等代码级和接口级信息
