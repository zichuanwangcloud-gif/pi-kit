# 严重级别与评级判据

发现的严重级别定义、S/A/B/C/D/F 的完整判据表，以及评级与门禁结论的组合规则。

> 由 SKILL.md 的「评级与严重级别」小节引用。

## 严重级别定义

| 级别 | 定义 | 典型例子 |
|---|---|---|
| `Critical` | 可导致 RCE、认证绕过、大规模敏感数据泄露、资金或权限的关键破坏 | 未鉴权的命令执行入口、任意用户可读全量数据 |
| `High` | 主要功能错误；需求项的实现或测试证据明确缺失；注入、越权、secret 泄露、关键数据破坏 | 核心分支逻辑反了、租户条件缺失、私钥进入仓库 |
| `Medium` | 重要边界错误、安全纵深缺口、明显回归风险 | 边界值处理错误、缺少二次校验、错误处理吞掉失败 |
| `Low` | 非阻断的质量问题或低风险改进 | 命名与结构问题、日志不足、可读性 |
| `Info` | 说明、假设、观察项或建议 | 既存问题（非本 PR 引入）、后续优化方向 |

判级要求：每条发现必须写 `file:line`、触发条件、实际影响与判级理由。
无法说明现实影响的条目降为 `Info`，不得用 `High` 充当「我觉得不太好」。

## 评级判据

| 等级 | 条件 |
|---|---|
| `S` | 所有启用 Gate PASS；无未验证项；测试与扫描完整；无有效警告 |
| `A` | 所有启用 Gate PASS；只有低风险提示或明确、非关键的验证限制 |
| `B` | 无 FAIL，但至少一个启用 Gate BLOCKED；其余启用 Gate PASS |
| `C` | 无 FAIL，但多个启用 Gate BLOCKED，或证据不足以支持合并判断 |
| `D` | 存在 FAIL，但影响有限、易修复，且无高危安全问题 |
| `F` | 存在关键正确性失败、明确需求缺失、鉴权/数据泄露/RCE 等高风险安全问题，或多个 Gate FAIL |

## 降级与封顶规则

- 任一未解决的 `Critical/High` → 对应 Gate `FAIL`，等级不高于 `D`；安全高危一律 `F`。
- 存在 `Low/Info` 但无阻断项 → 由 `S` 降为 `A`，不再继续下降。
- 项目没有专用安全 scanner、仅完成人工审阅 → 评级上限 `A`，不得 `S`。
- 存在未验证项（命令未跑、覆盖有限、fork 限制） → 不得 `S`。
- head 在审计期间漂移 → 总体 `BLOCKED`，不沿用旧等级。

## 与 PASS 计数的关系

- `DISABLED` 不降低评级，也不计入 PASS 数：`--linear off` 时两个启用 Gate 全部高质量通过即可 `S/A`。
- `BLOCKED` 与 `FAIL` 都不是 PASS，不得凑数，也不得用其他门的高分平均掉。
- 只有总体门禁 `PASS` 且等级为 `S/A` 时才输出「建议通过」。

## 评级依据的写法

报告的「评级依据」段必须回答两件事，缺一不可：

1. 为什么是这个等级——指向具体证据或具体缺口，不写「整体质量良好」这类空话。
2. 提升到上一等级需要哪些**具体动作**——例如「补 X 模块的回归测试」「在 CI 环境跑通 Y scanner」。
