# Multica 操作手册走查

用浏览器自动化把一个站点的主要操作走一遍，写成客户能照着做的手册。只写手册目录，不改仓库源码，不碰 git。

## 平台约定（Multica）

- **无交互用户。** 只有通过 `multica issue comment add` 发出的评论对人可见；确切命令（含 `--parent`）以运行时指令为准，正文用 `--content-stdin` 加 heredoc 传入。
- 读上下文：`multica issue get <id> --output json`、`multica issue comment list <id> --output json`。
- 取代码：`multica repo checkout <url>`，URL 取自运行时的 Repositories 表。issue 未指明仓库且候选不止一个时，按阻塞处理。
- 只在需要人做决定或补材料时才提醒人（需澄清、阻塞、超出自己权限），常规结果不提醒。写法：`[@名字](mention://member/<user-id>)`，id 取自 issue 的创建人字段与 `multica workspace members --output json`；创建人是智能体或查不到 id 时写纯文本名字。
- **不写任何 `mention://agent/` 链接**，它会重新触发智能体；提到其他智能体只写名字。
- issue 状态按运行时指令处理，本 skill 不额外改状态。
- 一轮只发一条结果评论。结论行是评论的最后一行，写法必须与本文给出的完全一致，其后不得再有任何字符。
- 评论写结论和证据，不写过程；阻塞类评论不超过 8 行。

## 开工前检查

三项都要有，缺任何一项就发阻塞评论并结束。评论里把缺的全部列出来，阻塞行写第一项：

| 需要 | 阻塞行 |
|---|---|
| 站点 URL（来自 issue） | `【手册】阻塞：缺少站点 URL` |
| 登录方式与角色（来自 issue 或运行环境已配置的凭据） | `【手册】阻塞：缺少登录凭据` |
| `deveye ping` 连通 | `【手册】阻塞：deveye 未连接` |

不要自己猜地址、注册账号或向人索要把密码贴进评论；请对方通过运行环境配置凭据。

## 走查

1. 先定范围：页面清单与每页的主操作。issue 没指定时取导航里的一级页面，并在评论里写明。
2. 自己开一个标签页并记下 tabId，之后所有 deveye 命令都带 `-t <tabId>`。不操作、不关闭别的标签页。
3. 每页：等页面加载完成（`deveye wait`）再截概览图；每个主操作一张图；弹窗和抽屉单独截。
4. 需要造数据时名称统一加 `demo_` 前缀，走查结束后删除，删不掉的列进「待清理」。
5. 不做不可逆操作：删除真实数据、改计费、改权限、发通知。遇到就截到确认弹窗为止。
6. 截图存 `img/<页序号>-<步序号>.png`，结束后查一遍重复帧。

## 手册怎么写

- 读者是客户：写「点哪里、填什么、会看到什么」，不写实现细节、内部代号和内网地址。
- 界面文案逐字照抄截图里的文字。
- 每一步对应一张图；没截到的步骤标「缺图」，不要用文字描述冒充。
- 走查中发现的问题（报错、文案不一致、死链）只记录，不修。

## 评论格式

```markdown
## 走查结果

- 站点：<URL>，角色：<角色>
- 范围：<N> 页，<M> 个主操作
- 手册：`<路径>`（<K> 张截图）

### 走查发现
| 级别 | 页面 | 问题 |
|---|---|---|
没有就写「无」。

### 未完成与待清理
没有就写「无」。

【手册】<路径>
```

最后一行只有两种写法：`【手册】<路径>`、`【手册】阻塞：<原因>`。

## 出错时

| 情况 | 处理 |
|---|---|
| 个别页面打不开 | 记入走查发现，继续其余页面 |
| 登录失败 | `【手册】阻塞：登录失败` |
| 站点不可达 | `【手册】阻塞：站点不可达` |
