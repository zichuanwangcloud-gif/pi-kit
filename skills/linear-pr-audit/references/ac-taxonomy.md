# 验收标准分型与默认验证方式

按 AC 类型固定验证方式、结论上限和必填限制项，防止把「跑了一下没报错」当证据。

先给每条 AC 定型，再按本文件对应小节取默认验证方式。定不了型就停止询问，不自选口径。
本文件的片段与其他 reference 一致：首行 source **字面路径** `/tmp/pi-linear-pr-audit-pr-<PR>.env`
（`. "$ENVFILE"` 在新 shell 里等于 `. ""`）并断言用到的每个变量，**不使用 `set -e`**，
闸门一律 `cmd || { echo "STOP: ..."; exit 1; }`。

## 功能性、确定性 AC

识别关键词：能/支持/返回/显示/校验/拒绝/落库/导出/状态流转、明确的输入与期望输出。

四级阶梯，只能向下降级，且必须写明为什么上一级不可用：

| 优先级 | 验证方式 | 证据形态 | 结论上限 |
|---|---|---|---|
| 1 | 自动化测试（项目既有框架） | 命令 + 基线 exit + 修复后 exit | `PASS` |
| 2 | 可复现命令（CLI / HTTP / 脚本） | 完整命令 + 实际输出片段 | `PASS` |
| 3 | 数据/状态断言（schema、配置、迁移结果、生成物） | 查询语句 + 返回值 | `PASS` |
| 4 | 人工复现步骤 | 精确步骤 + 实际观察结果 | `PASS`，等级上限 A |

必填限制项：断言的必须是 AC 描述的**用户可观察行为**，不是内部函数返回值。
只测到内部返回值 → 记 `BLOCKED`，说明缺哪一层可观察断言。

降到第 4 级（人工复现步骤）时**评级上限 A**。该条已登记进 SKILL.md「通过规则与评级」的
上限清单；本文件新增任何上限规则都必须同步登记到那份清单，否则以那份清单为准。

## 非功能性 AC

| 子类 | 识别关键词 | 默认验证方式 | 结论上限 | 必填限制项 |
|---|---|---|---|---|
| 性能/容量 | 延迟/QPS/P95/并发/内存/超时 | 同一机器上对 `baseRefOid` 与 head 各跑 ≥10 次、前 3 次预热丢弃，报告**相对 base 的** P95 变化 | 见下方相对口径判定表 | 必须写明机器规格、数据规模、预热与样本数、阈值与原始样本序列 |
| 浏览器/设备/OS 兼容 | Chrome/Safari/iOS/Android/分辨率 | 仅当项目既有 e2e 矩阵已覆盖该目标时才跑 | 矩阵未覆盖 → `UNVERIFIABLE` | 列出矩阵实际覆盖的目标，不得外推 |
| 可访问性 | a11y/WCAG/AA/对比度/屏幕阅读器 | axe / pa11y 等项目既有工具 | `PASS(partial)` | 必须枚举未自动覆盖的准则 |

性能规则（硬性）：

- **相对口径必须有判定阈值。** 只说「报告相对变化」而不给判定线，等于把结论权交回主观感觉。
  设 `Δ = (head P95 - base P95) / base P95`：

  | 观察 | 判定 |
  |---|---|
  | 样本标准差 > 均值的 30%（任一侧） | `BLOCKED`——机器噪声过大，本机测不出结论，不得据此判 PASS 或 FAIL |
  | `Δ` ≤ 5% | `PASS` |
  | 5% < `Δ` ≤ 20% | `PASS` + 一条 Medium 发现 + 限制项（写明退化幅度与建议压测环境） |
  | `Δ` > 20% | `FAIL` |

  先判噪声再判 `Δ`。阈值、base/head 两侧的 P95、标准差与**原始样本序列**全部进报告；
  只贴一个百分比不成立。
- **绝对阈值不得在审计机上判定。** 「P95 < 200ms」在审计机上跑出 180ms 不能判 `PASS`——
  CPU、缓存、数据规模、并发背景全不同。无法在本地判定的绝对阈值一律 `UNVERIFIABLE`，
  并写明需要谁在什么环境压测。
- **性能不达标不进入修复循环。** 优化必然超出「让已声明验收标准成立所必需的最小改动」边界；
  只输出缺口与建议方向，交回用户决定。

可访问性规则：自动化工具只覆盖 WCAG AA 的**一个子集**，结论只能写
「在 <工具+版本> 的自动检查项上未发现违规」，**永远不得写「符合 AA」**。
必须逐项列出未自动覆盖的准则，至少包括：键盘陷阱、焦点顺序、阅读顺序、
仅靠颜色传达信息、动态内容播报、复杂控件的语义角色。

## 负向 AC

识别关键词：必须不 / 禁止 / 不得出现 / 不应记录 / 不允许访问 / 无泄露。

**「跑了一遍，没发现」不是证据。** 未执行到的分支、没被采集的 sink、写错的匹配模式，
三者产出的绿色完全一样。负向 AC 必须同时具备三件证据，缺一即 `BLOCKED`：

1. **触发正样本**：证明被禁止的那条路径**确实执行过**。给出触发命令 + 路径被执行的痕迹
   （日志行、覆盖率、计数器、断点断言），不能只说「调用了接口」。
2. **哨兵正对照**：把一个唯一哨兵值注入**同一个 sink**，确认检测器**能**命中它。
   正对照未命中 → 检测器无效，本条 AC 的所有绿色结论作废。
3. **负断言 + sink 枚举**：断言哨兵之外无违规命中，并逐个列出已覆盖的 sink。

```bash
. /tmp/pi-linear-pr-audit-pr-<PR>.env; : "${WT:?}" "${SINKS:?}" "${FORBIDDEN_PATTERN:?}"   # SINKS：每行一个 sink 路径的清单文件
SENTINEL="pi-sentinel-$(date +%s)-$RANDOM"
# 1) 触发正样本
<触发命令> || { echo "STOP: 禁止路径未能被触发，负向 AC 无法验证"; exit 1; }
# 2) 正对照：哨兵必须被检测器命中
<注入哨兵命令> || { echo "STOP: 哨兵注入失败"; exit 1; }
xargs -a "$SINKS" -d '\n' grep -rqF -- "$SENTINEL" \
  || { echo "STOP: 正对照未命中，检测器无效"; exit 1; }
# 3) 负断言
HIT=$(xargs -a "$SINKS" -d '\n' grep -rEn -- "$FORBIDDEN_PATTERN" | grep -vF "$SENTINEL" || true)
[ -z "$HIT" ] || { printf 'FAIL: 在已枚举 sink 上发现违规命中：\n%s\n' "$HIT"; exit 1; }
```

`SINKS` 是**清单文件路径**，不是空格分隔的路径串——后者会在 `grep -r "$SINKS"` 处被词分割，
含空格的 sink 路径直接漏检。清单文件与 `FORBIDDEN_PATTERN` 现场赋值后追加进 `$ENVFILE`。

sink 清单必须逐项声明覆盖与否：stdout、stderr、文件日志、APM/tracing、
错误上报（Sentry 等）、HTTP 响应体与响应头、数据库字段、消息队列、审计日志。
未覆盖的 sink 逐条写进限制项。

结论措辞：只能写「在 <已枚举 sink> 上未发现 <模式>」，
**不得**写「不泄露 PII」「无敏感信息」这类全局断言。

## 多主体 / 异步 / 有状态 AC

| 子类 | 识别关键词 | 默认验证方式 | 强制断言 | 结论上限 |
|---|---|---|---|---|
| 多用户/多角色 | 管理员/普通用户/租户/越权/可见性 | 为每个主体建立**独立 session**，不复用 token | 必须含**跨主体负向断言**（A 的资源 B 取不到） | 缺负向断言 → `BLOCKED`，权限等于没测 |
| webhook 入站回调 | webhook/回调/签名/重放 | 本地起接收端，构造真实签名请求 | 签名校验断言 + 重放幂等断言（同一 payload 二次投递） | 缺任一 → `BLOCKED` |
| cron 定时任务 | 定时/每日/cron/调度/延时 | 断言调度表项存在 + 注入假时钟触发任务体 | 禁止 `sleep` 等真实时间 | 「本地手动跑了一次」不是「按时触发」的证据 |
| 邮件/通知 | 邮件/短信/推送/通知 | outbox 或 mock transport 捕获 | 断言收件人、模板、变量渲染 | 项目无 outbox/mock 机制 → `BLOCKED`，不是 `UNVERIFIABLE` |

绝不真实发件、真实扣款、真实调用第三方写接口。

异步 AC 通用规则：

- 用**轮询直到条件成立 + 超时上限**，禁止固定 `sleep` 当同步手段。

```bash
. /tmp/pi-linear-pr-audit-pr-<PR>.env; : "${WT:?}"
DEADLINE=$((SECONDS + 60))
until <条件命令>; do
  [ "$SECONDS" -lt "$DEADLINE" ] || { echo "FAIL: 超时未达成条件"; exit 1; }
  sleep 1
done
```

- 必须**连续 3 次**通过。任意一次抖动 → `BLOCKED`，并记录观察到的抖动率（如 `1/3`），
  不允许「重试到绿」后判 `PASS`。

## 定型不清时

同一条 AC 同时落在多个分型（例如「导出必须在 3 秒内完成且不含手机号」）→ 按 SKILL.md 的拆分规则
先拆成原子 AC，各自定型；拆不开就停止询问。
