# E 节：极端条件——故障矩阵逐格打勾

「极端条件」不能靠想象，要变成一张可以逐格打勾的表。AI 默认世界是干净的：数据库永远在、上游永远返回合法 JSON、请求永远不会中途断开、表里永远有数据也永远不会太多。每一格都是它没想过的一种世界。

> 由 SKILL.md 的 E 节引用。**只对 `$TARGET_ENV` 指定的隔离环境注入**，未指定则整节 `BLOCKED`。

## 隔离前提（闸门）

注入故障前必须证明目标环境隔离。至少核对：数据库连接串指向的主机/库名不在共享清单里、进程监听端口不是共享环境的、没有指向生产的上游地址。

```bash
. /tmp/pi-pr-verify-<ID>.env; : "${TARGET_ENV:?}" "${PACK:?}"
echo "target env: $TARGET_ENV" | tee "$PACK/fault-env.out"
<打印该环境有效配置里数据库/缓存/上游地址的命令> | tee -a "$PACK/fault-env.out"
HIT=$(grep -iE '<共享或生产环境的主机名/库名模式>' "$PACK/fault-env.out" || true)
[ -z "$HIT" ] || { echo "STOP: 目标环境配置命中共享/生产地址，禁止注入"; exit 1; }
```

模式由用户给出；给不出就询问，不猜。

## 三条通过标准

每格同时满足才 `PASS`：

1. **不 panic、不 crash loop**：进程存活或按预期退出并被拉起，日志无未捕获异常堆栈反复出现。
2. **状态一致**：涉及资金、计数、配额、状态机的表，故障前后可对账——写一条对账查询，故障前后各跑一次，落进结果文件。
3. **自愈**：故障移除后，不重启进程，同一请求在 N 秒内恢复成功（N 取配置的重连/熔断恢复时间）。

只满足第 1 条记 `PASS(degraded)` 并在报告说明；第 2 条不满足直接 `FAIL`，无论其他。

## 制造手段

优先项目已有的手段（compose profile、chaos 脚本、测试用 mock server）。通用手段：

- 网络层：toxiproxy（延迟/断连/半截）、`tc qdisc add dev <iface> root netem delay 500ms`；
- 进程层：`docker stop`/`kill -STOP`（挂起比杀死更像真实故障）/`kill -9`；
- 资源层：`ulimit -n 64`（fd 耗尽）、`mount -t tmpfs -o size=1m`（磁盘满）；
- 并发：压测工具固定 key 打同一资源；Go `-race`、Rust loom、JS 双击脚本；
- 时钟：项目若注入 clock 接口用它；否则 `faketime` 或容器内改时间。

工具缺失 → 该格 `BLOCKED(no-tool)`，写明缺什么；不自动安装。每格的制造命令、观察命令、恢复命令三段都进结果文件。

## 与本 PR 无关的行

矩阵是通用模板，不是每行都与本 PR 相关。规则：

- 「触发的验收表行」能填 → 必须跑；
- 填不了 → 标 `N/A` 并写一句原因（如「本 PR 无流式路径」）；
- **不得整节跳过**。`N/A` 的判断由本会话做并在报告列出，用户可以推翻。

## Soak

正常负载持续 ≥30 分钟（用 D 节的 `LOAD_CMD` 降低并发即可），每 5 分钟记一次内存、连接数、fd 数、错误率。曲线应平；单调上升 → `FAIL(leak)`，附读数序列。

## 判定

| 结果 | 条件 |
|---|---|
| E 节 `PASS` | 所有非 `N/A` 格 `PASS` 或 `PASS(degraded)`，Soak 平 |
| E 节 `FAIL` | 任一格状态不一致、panic/crash loop、不自愈，或 Soak 泄漏 |
| E 节 `BLOCKED` | 无 `TARGET_ENV`，或关键格因工具缺失无法制造 |

报告里每格给出：制造命令、观察到的现象（原始日志行）、对账查询前后结果、恢复耗时。
