# B 节：链路接通——每一层都对，整体不对

AI 代码最常见的「没做完」不是缺功能，是链路断在中间：handler 收了字段、service 有参数、repository 有列，各层单测全绿，但字段从没被写进 SQL，或写了没读回，或读回了前端没渲染。分层单测的设计前提是「错误是局部的」，这类错误恰好不局部。

> 由 SKILL.md 的 B 节引用。输入：`$TABLE`、`$DIFF`、`$CONVENTIONS`、`$WT_HEAD`。

## 静态追链（独立上下文）

追链者只拿三样输入，不拿 PR 描述、不拿实施过程。提示词：

```text
下面是一张验收表、一个 diff 和项目约定摘录。对表里每一行，从请求入口开始，追到持久化（或外部调用），再追回响应/渲染，列出经过的每一个函数，格式 `文件:行号 函数名 —— 它对这一行的贡献`。
规则：
1. 只认代码，不认注释、不认 PR 描述、不认变量名暗示。
2. 任何一段找不到代码的，标「未接上」并写明断在哪两层之间。
3. 字段级追踪：新增或修改的每个字段，要指出它被读取的位置、被写入的位置、被返回的位置，缺任一即「未接上」。
4. 如果某一行的链路完全不经过 diff 里的任何文件，标「diff 无关」——这一行要么是 base 已有能力，要么表越界。
5. 不要评价代码质量，不要建议修改。
```

追链者输出回来后，本会话核对：每条 `文件:行号` 在 `$WT_HEAD` 里真实存在且内容相符（抽查至少三处），不相符的整段追链作废重做。

## 「未接上」的判据

| 现象 | 判定 |
|---|---|
| 请求结构体/DTO 有字段，service 层函数签名没有它 | 未接上（入口→业务） |
| service 传了字段，repository/SQL/ORM 调用没用它 | 未接上（业务→持久化） |
| 列存在于迁移，但没有任何读路径返回它 | 未接上（持久化→响应） |
| 响应含字段，前端类型定义有它，但没有组件渲染它 | 未接上（响应→渲染） |
| 字段被读取但只用于日志 | 未接上（除非验收表期望就是日志） |
| 链路经过的是 mock/stub/feature-flag 关闭分支 | 未接上（生产形态不可达） |
| 接口存在，路由表里没注册 | 未接上（入口缺失） |
| 路由注册了，但被更早的 catch-all/静态兜底吞掉 | 未接上（须用真实构建形态验证，见下节） |

最后一条要特别说明：SPA fallback、`/*` 静态兜底、反代规则会让「路由代码存在」与「路由实际可达」分家，而且**只在生产构建形态下出现**（开发模式常绕过静态兜底）。静态追链发现新增路由时，真跑必须用 `BUILD_CMD` 的产物而非开发服务器。

## 按表逐行真跑

在 head worktree 上以生产形态构建并启动服务：

```bash
. /tmp/pi-pr-verify-<ID>.env; : "${WT_HEAD:?}" "${BUILD_CMD:?}" "${PACK:?}"
( cd "$WT_HEAD" && eval "$BUILD_CMD" ) > "$PACK/build-head.out" 2>&1; EXIT=$?
echo "build exit=$EXIT"; tail -5 "$PACK/build-head.out"
[ "$EXIT" -eq 0 ] || { echo "STOP: head 生产形态构建失败，B 节无法真跑"; exit 1; }
```

启动方式按项目文档（`RUN_CMD` 一类由用户或文档给出，落到 `URL_HEAD`）。需要数据库/缓存的，用隔离实例，禁止指向共享环境。

每一行转成一条断言脚本，输出落 `$PACK/chain-<行号>.out`。HTTP 行的模板：

```bash
. /tmp/pi-pr-verify-<ID>.env; : "${URL_HEAD:?}" "${PACK:?}"
ROW='<行号>'; OUT="$PACK/chain-${ROW}.out"
CODE=$(curl -sS -o "$OUT.body" -w '%{http_code}' -X '<方法>' "$URL_HEAD<路径>" -H 'Content-Type: application/json' -d '<请求体>')
echo "http=$CODE" > "$OUT"; cat "$OUT.body" >> "$OUT"
echo "http=$CODE"; jq -r '<期望字段的 jq 路径>' "$OUT.body"
```

判定由本会话对照 `$TABLE` 该行的期望列做，**把期望值和实际值并排写进报告**，不写「一致」两个字。

UI 行用项目既有 e2e 框架（Playwright/Cypress/其他）写一次性脚本放在仓库外，断言写法见下节；截图落 `$PACK/`。

## 断言字面值，不断言结构

| 不算证据 | 算证据 |
|---|---|
| 「接口返回了 200」 | `http=201` 且 `body.total == 200` |
| 「函数被调用了」（spy/mock 断言） | 调用后可观察的状态：DB 行、响应字段、DOM 文本 |
| 「组件接收到了 prop」 | 渲染结果：`input.value === "00:00-24:00"`、元素文本 |
| 「配置传进去了」 | 配置生效后的行为差异（改配置 → 输出变） |
| 「日志里打印了成功」 | 日志行 + 被日志描述的那个状态本身 |

UI 尤其要断言 `input.value`/`textContent` 字面值。控件库大版本升级后 prop 名、配置对象结构会变，「传了没生效」在结构断言下全绿，在字面值断言下必红。

## 负向行的真跑

负向行（权限/开关/幂等/泄露）要同时拿到两样：

1. 期望的「不发生」：`http=404`、响应无该字段、第二次请求不新增行。
2. **路径确实执行过的痕迹**：请求日志里有该路由、计数器加一、覆盖率命中。

只有第一样时记 `BLOCKED`——「没跑到」和「没发生」产出的绿色完全一样。

幂等行的模板：

```bash
. /tmp/pi-pr-verify-<ID>.env; : "${URL_HEAD:?}" "${PACK:?}"
ROW='<行号>'; OUT="$PACK/chain-${ROW}.out"; KEY="idem-$$"
for i in 1 2; do
  curl -sS -o "$OUT.$i" -w "try$i http=%{http_code}\n" -X POST "$URL_HEAD<路径>" -H "Idempotency-Key: $KEY" -H 'Content-Type: application/json' -d '<请求体>'
done | tee "$OUT"
<查询落库行数的命令> | tee -a "$OUT"
```

期望：两次响应等价，落库行数为 1。

## 落盘与判定

| 行状态 | 条件 |
|---|---|
| `PASS` | 追链完整（无「未接上」）且真跑输出与期望列字面一致 |
| `FAIL` | 任一「未接上」，或真跑值不符 |
| `BLOCKED` | 构建/启动失败，或负向行缺执行痕迹 |
| `diff 无关` | 追链不经过 diff；不计入 B 节分子分母，转报告「越界声明」段并回查 A 节来源 |

B 节 `PASS` = 全部计入行 `PASS`。报告里每行给出：追链摘要（首尾两个 `文件:行`）、`$PACK/chain-<行号>.out` 文件名、期望值、实际值。
