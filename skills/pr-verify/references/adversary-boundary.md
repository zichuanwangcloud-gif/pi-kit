# C 节 · 对抗审查、边界矩阵、鉴权、范围与反推需求

这四项都要求**独立上下文**：同一上下文里的 AI 有强烈的自我确认，它「记得」自己处理了某件事就不会再查。验证者只拿 `$TABLE`、`$DIFF`、`$CONVENTIONS` 三样，不拿实施过程。本会话的职责是把验证者给出的输入**真的跑一遍**并落盘。

## 独立上下文的执行方式

| 运行时 | 做法 |
|---|---|
| 提供子代理/任务派生工具 | 用它起一个**非 fork、不继承本会话上下文**的代理，prompt = 本文对应提示词 + 三样输入的文件内容。收结果落 `$PACK/`。 |
| 不提供 | 把提示词与三样输入打包成一个文件 `$PACK/verifier-<项>.prompt.md`，请用户在新会话粘贴运行，把输出粘回。本会话等待，不代跑。 |

报告必须写明每项用的是哪种方式。本会话自己扮演验证者的结果一律降为 `NOT-RUN`。

## 对抗审查

提示词：

```text
下面是一个 diff、它声称满足的验收表和项目约定摘录。假设这段代码里一定有 bug。
列出你认为最可能出错的 5 个位置，每个给出：
- `文件:行号`
- 你怀疑的失败机制（一句话）
- 一组能触发它的具体输入（HTTP 请求体 / 函数参数 / 命令行 / UI 操作序列，要能直接执行）
- 触发后你预期看到的错误现象
不要评价风格，不要建议重构，不要说「可能需要更多测试」。找不到 5 个就列出找到的，并说明剩余部分为什么你认为安全。
```

本会话对每组输入在 head 服务/测试环境上执行，输出落 `$PACK/adversary-<n>.out`，并排记录「验证者预期现象 / 实际输出」。实际输出与预期错误现象吻合 → 该项 `FAIL`，附输入与输出；不吻合 → `PASS`。五项都跑完才算此格有结论。

## 边界矩阵

提示词：

```text
对 diff 里每个新增或修改的输入字段（请求参数、配置项、函数参数、UI 输入），逐字段回答以下每一列在代码里是怎么处理的，给出处理它的 `文件:行号`；没有处理的写「未处理」：
空字符串 | null/缺省 | 0 | 负数 | 最大值+1 | 超长字符串（如 10k 字符）| Unicode/emoji/组合字符 | 前后空白 | 并发重复提交 | 时区边界（23:59:59、跨日、跨月、DST）
额外两行：该字段被持久化时的列类型与长度限制；该字段被返回时是否原样回显。
```

输出是一张字段 × 边界的表。本会话对每个「未处理」格构造输入真跑，落 `$PACK/boundary-<字段>-<边界>.out`。判定：

- 未处理格真跑出 5xx、panic、数据截断、静默接受非法值 → `FAIL`；
- 未处理格真跑出 4xx 且错误码明确 → 验证者判断有误，记 `PASS` 并注明；
- 「原样回显」列为「是」且字段可含用户输入 → 转 `pr-audit` Security 关注点，本节记录不判定。

## 鉴权四列表

AI 照旁边的 handler 写新 handler，业务逻辑抄对了，但中间件、权限点、租户过滤三样常缺一样；单测里鉴权又被 mock 掉。提示词：

```text
列出 diff 新增或修改的每个路由/RPC 方法/任务入口，四列：
路由 | 挂了哪些中间件（给注册处 文件:行）| 检查了哪个权限点/角色（给检查处 文件:行）| 数据查询里是否带租户/所有者过滤（给 SQL/ORM 调用处 文件:行）
任一列找不到代码写「缺」。对照项目约定摘录里的鉴权中间件名与惯例，指出与同目录既有路由不一致的地方。
```

本会话对每个「缺」用**低权限账号真打一遍**（`URL_HEAD` + 该角色凭据），落 `$PACK/authz-<路由>.out`。低权限能进 → `FAIL`；不能进但表里写「缺」→ 验证者漏看了某层，补 `文件:行` 后记 `PASS`。

## 范围二分

diff 里与需求无关的改动——顺手重命名、顺手调格式、顺手「修」了它认为的 bug——每一处都是未经评审的行为变更。提示词：

```text
把 diff 按 hunk 分成两栏：「验收表某行必需」（写出行号）与「顺手改的」（写出改了什么）。
判据是能否指到验收表的某一行；指不到就是顺手改的，哪怕它看起来是改进。
```

输出落 `$PACK/scope-split.md`。「顺手改的」栏非空 → 报告「未决问题」段逐条列出，请用户裁决拆 PR / 删除 / 补进验收表。不裁决前该格 `BLOCKED`。

## 反推需求

需求说 A，AI 做了一个很像 A 的 A′，再为 A′ 写测试。验收表能拦一部分，反推能拦另一部分。提示词（**只给 diff 与约定摘录，不给验收表**）：

```text
只读这个 diff。用一段话和一张「操作 | 输入 | 结果」表描述：这段代码实现的需求是什么。
不要猜作者意图，只写代码实际会做的事。发现代码行为与你直觉上的「合理需求」不一致时，如实写代码的行为。
```

本会话把反推表与 `$TABLE` 并排比对，差异分三类：

| 差异 | 处置 |
|---|---|
| 反推有、验收表无 | 越界实现，转范围二分 |
| 验收表有、反推无 | 未实现或未接上，与 B 节结论交叉核对 |
| 同一操作结果不同 | 需求漂移，`FAIL`，报告并排给出两种描述 |

## 判定

| 子项 | `PASS` 条件 |
|---|---|
| 对抗审查 | 五组输入全部真跑，无一复现验证者预期的错误现象 |
| 边界矩阵 | 全部「未处理」格真跑，无 5xx/panic/截断/静默接受 |
| 鉴权四列表 | 无「缺」，或每个「缺」低权限真打被拒 |
| 范围二分 | 「顺手改的」栏为空，或每条已获用户裁决 |
| 反推需求 | 与验收表无第三类差异，前两类已归入对应节 |

任一子项 `FAIL` → C 节 `FAIL`。
