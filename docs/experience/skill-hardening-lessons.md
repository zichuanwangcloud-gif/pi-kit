# Skill 加固经验：写得对 ≠ 能执行

本文记录一轮对 `linear-to-pr` / `linear-pr-audit` / `pr-audit` 的系统加固中，
**只有实际执行才能发现、通读永远发现不了**的缺陷类型。全部结论都在一次性 scratch 仓库里实测过。

写新 Skill 或改这三个 Skill 前应先读本文，它能省掉一整轮返工。

## 一、核心教训

**通读「关于机械化强制的散文」不等于验证了机械化强制。**

这一轮里有三个缺陷通过了一次红队评审、一次独立审计和作者自查，因为它们**长着正确的样子**：

1. 一个闸门写成 `cmd && echo "STOP: ..."`——命中与不命中**都返回 0**，流程照常走到 commit/push。
2. 一个「唯一权威」参数模板，第一个 source 它的片段在它被创建之前执行。
3. 一个外发脱敏闸门，模式集合完全正确，但检测器是 shell 函数——函数不跨 `bash` 调用，
   未定义时 `HITS` 为空，闸门放行，未脱敏报告直接发出去。

因此现在有 `tests/skill-snippets.mjs`：抽出全部 ```bash 片段，逐个 `bash -n`，
并把每个被读取的 `$VAR` 对照「本片段内赋值 + 该 Skill 声明的 env 文件契约」核对。
**加规则的同一个 PR 必须让这个检查保持绿色**，否则规则只是散文。

## 二、已实测的事实（不要重新推导）

| 断言 | 实测结果 |
|---|---|
| `git -C ""` 会报错 | **假。rc=0，静默回退到当前目录。** `WT` 为空 + `BR` 有值 → 从主工作区推送 |
| `git -C "" push -u origin "refs/heads/:refs/heads/"` | `fatal: invalid refspec`，rc=128（这个方向是安全的） |
| linked worktree 的 `$GIT_DIR/info/exclude` 可写 | **假。`info/` 目录不存在，重定向直接报错** |
| 补建目录后 git 会读它 | **假。git 只读 `--git-common-dir` 那份，即主仓库的文件** |
| `git config --worktree` 可干净恢复 | **假。它要求先启用仓库级 `extensions.worktreeConfig`，`--unset` 不会移除该 extension，永久残留** |
| `git worktree add "$WT" "<branch>"` 在该分支已被 checkout 时可用 | **假。`fatal: already checked out`**。改用审计专用分支指向冻结 oid |
| `show-ref --verify refs/heads/a/b` 能查出 `a` 被占用为扁平分支 | **假。rc=1（不存在），随后 `worktree add -b` 才失败 rc=255** |
| `set -euo pipefail` 下 `( cd X && cmd ); EXIT=$?` 能取到退出码 | **假。在子 shell 处直接中止，永远走不到 `EXIT=$?`**。需 `set +e` … `set -e` 窗口 |
| `timeout 0 <cmd>` 是「立刻超时」 | **假。是「永不超时」。** 变量未赋值算出 0 时，等待变成无限阻塞 |
| `gh pr checks` 有超时参数 | **假。没有。** `--watch` 阻塞到落定，只能外套 `timeout` |
| `gh pr checks` 退出 0 等于全绿 | **假。`skipping` 算非失败**，全 skip 也退 0。判据必须取 `bucket` 明细 |
| `gh auth status` 成功说明 origin 托管在 GitHub | **假。它只验证 github.com 凭据**，origin 指向 GitLab 时同样成功 |
| `cmd >/dev/null 2>&1 && echo x` 变量为空时能看出异常 | **假。什么都不打印**，与「检查通过」完全无法区分 |
| `test -f X && <失败命令> \|\| echo "无"` | 命令失败也打印「无」。探测与动作必须分开 |
| 暂存区为空时能通过「无命中」闸门 | **是。** 忘记 `git add` 读起来等于闸门干净，需单独断言非空 |
| `"...PR-1234:x".includes("...PR-123")` | **真。** 前缀匹配必须带尾部 `:` |

## 三、必须遵守的写法

- **闸门一律 `cmd || { echo "STOP: ..."; exit 1; }`。** 需要「必须无命中」时先收进变量再判空：
  `HIT=$(cmd || true); [ -z "$HIT" ] || { echo "STOP: ..."; exit 1; }`。
- **探测与闸门分开**：探测 `... && echo yes || echo no`，永不中止；闸门必须能 `exit 1`。
- **每次 `bash` 调用都是新 shell。** 变量、函数、`cd` 全部不跨调用。
  取退出码的那一行要用 `set +e` 包住；同一节里两个 ```bash 围栏之间变量也不共享。
- **参数固化分阶段**，且阶段一必须先于第一个 source 它的片段；`ENVFILE` 必须写进它自己。
- **所有 git 命令带 `-C`**，不靠 `cd` 保证工作目录（见上表第一行）。
- **不用 `${VAR,,}`** 等 bash 4 专有语法（macOS 自带 bash 3.2 直接语法错误）。
- 私有临时文件一律 `mktemp` + `umask 077`，禁止可预测的固定名。

## 四、改文档时的两个陷阱

1. **修正一节内容时必须删掉旧的那节，不要在旁边追加。** 这一轮里
   「flaky 判定」一度在同一个文件里存在两份，各自声明「唯一允许的路径」，
   而目录指向的是被禁止的那一份。
2. **正文行数上限贴到边界会制造矛盾。** 每个修正都要用一次删除来支付时，
   最省力的动作就变成「在旧文旁边追加」。先腾出余量，再改语义。

## 五、评分/自评纪律

给能力打分时，**任何维度的得分不得高于它的片段被粘进 scratch 仓库执行后应得的分**。
本轮作者自评 +50.7%，独立审计复核后为 +37.3%，差距几乎全部落在三个「被当作证据引用、
但一跑就失败」的产物上。基线必须逐格对照 `git show HEAD:` 核实，避免为了放大改进而压低基线。
