# 用例格式

每个用例一个文件：`cases/NN-slug.md`，含 `public` 与 `hidden` 两部分。
`public` 是评委（被测方）能看到的全部输入；`hidden` **只能给需求方 agent**，不得进入被测方上下文。

```markdown
## public
title: <短标题>
trigger: <用户实际会打的那一句话或场景描述，含情绪和模糊性>

## hidden

### 问题与目标结果
谁 / 场景 / 损失 / 绕行方式；解决后可观察的变化。

### 事实（问就答，不问不给）
- K1 <可度量或可判定的事实> ｜ 类型：事实 ｜ 可问性：直接回答
- K2 ... ｜ 类型：业务取舍 ｜ 可问性：可回答，但只在你给出具体例子或选项时给出取向
- K3 ... ｜ 类型：未知 ｜ 可问性：需求方也不知道，只能靠探查
- K4 ... ｜ 类型：只对特定角色 ｜ 可问性：不是对话者能拍板的

### 验收标准（需求方自己的口径）
- 需求方认为「做好了」的判定条件，逐条写。

### 范围外
- 需求方明确不要或以后再说的事。

### 需求方立场
- 需求方是谁（可能不是对话者）、情绪、有没有权限拍板、会不会反问。

### 陷阱
- 为什么这个用例难：最容易出现的错误理解、最容易编造的细节。
```

## 字段的用途

| 字段 | 谁用 | 用来判断 |
|---|---|---|
| `public` | 被测方 | 唯一的输入 |
| 事实 `K*` | 需求方 agent | 召回率：哪几条被问出来了 |
| 事实类型「未知」 | 需求方 agent + 评委 | 是否正确转成探查，而不是硬编 AC |
| 范围外 | 评委 | 边界是否画对了 |
| 陷阱 | 评委 | 该用例的核心失败模式是否发生 |

## 事实类型的含义

- **事实**：需求方知道且能明确回答。
- **业务取舍**：需求方有取向，但抽象地问会得到「都行」「越快越好」这类无效回答；给出具体例子或选项才能得到真取向。
- **未知**：需求方也不知道，只有做了才知道。正确的处置是探查或列入未决，**不是**编一个 AC。
- **只对特定角色**：这条事实的决策人不是对话者本人（例如法务、平台组、客户），
  正确的处置是放进需求方确认清单，而不是替对方拍板。
