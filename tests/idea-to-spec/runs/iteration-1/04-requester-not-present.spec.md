# 客户要的结算数据目前没有可交付的出口，只能靠人工取数

> 状态：待需求方确认 ｜ 更新于 2026-10-13 ｜ 收敛轮数 1

## 问题
转述人说要「客户要一份数据」，但结算后台当前唯一的数据出口是 `GET /settlements`——只返回当前登录租户的 JSON 列表，注释里也写明「没有对外导出的能力」（`src/routes/settlement.ts:6-9`），导致这类「客户要数据」的诉求在系统里没有可交付的出口。具体是哪个客户、要哪一段、交给谁，只有需求方知道，本轮没有拿到（[推断]）；目前靠人工取数应付（[推断]，待确认）。[来源：用户原话 + 代码取证]

## 目标结果
- G1 客户要的那份结算数据能被交出去，且这份数据与后台现有出口 `GET /settlements` 的口径一致。[来源：用户原话 + 开发者判断]
- G2 交付过程不越出多租户边界：一个租户的数据不会落到另一个租户或无权限方的可见范围内。[来源：代码取证 `AGENTS.md`、`src/routes/settlement.ts:8`]

## 现状
- 入口：`GET /settlements` — `src/routes/settlement.ts:7`
- 生效实现：`src/routes/settlement.ts:8` 调 `listSettlements({ tenantId: req.user.tenantId, month: req.query.month })`；该函数的实现文件不在仓库里（`src/services/` 为空目录），返回字段无法进一步确认。
- 当前行为：按「当前登录租户 + month 查询参数」返回结算列表 JSON。`src/routes/settlement.ts:6` 的注释确认「只能读当前登录租户的数据 —— 没有对外导出的能力」；全仓 grep `export|csv|xls|download|导出` 只命中这条注释本身，没有任何导出实现。
- 取证边界：仓库是桩仓库（`AGENTS.md`），只有这一个路由文件。因此「有哪些字段」「该租户该月多少条」都无法由代码取证，只能由需求方回答。

## 候选方案
- 采用：在现有的同租户结算出口上新增受控导出——复用 `req.user.tenantId` 的租户过滤与 month 筛选口径，产出文件供下载。理由：现有接口已自带租户边界与筛选口径，复用可避免另开一条没有边界校验的数据通道；这也是仓库里唯一有证据可落的地方。
- 放弃：绕开应用层直接连库或手工捞数交付。理由：无租户边界校验、无留痕、每次都要人来一遍，行为无法沉淀成可复验的东西。
- 待定（不替需求方拍板）：本次可能只是「一次性要一份数据」而不是产品化能力。若确为一次性，本 spec 不适用，应走一次性取数流程——见需求方确认清单 E1。

## 约束（非功能）
- 权限：导出必须复用现有的租户身份判定（`req.user.tenantId`），不得新增匿名通道或跨租户通道。相关。
- 数据敏感：文件里能出现哪些字段取决于给谁看；是否要裁掉内部字段（成本、内部备注、内部编号）尚无需求方口径，见确认清单 E2/E3。相关。
- 可观测性：导出是否留痕（谁、何时、导了哪个租户的数据）尚无口径，见确认清单 E4。相关。
- 兼容：不得改变 `GET /settlements` 的现状（由 AC5 守住）。相关。
- 性能：不相关到写不成 AC——数据规模与可接受时长都没有任何来源，不编造阈值（见未决 Q2）。
- 数据迁移：不相关——本需求不改变存储结构。

## 范围外
- 跨租户 / 全量导出：不做——与 `AGENTS.md`「每个租户只能看自己的数据」直接冲突。
- 给外部客户开后台账号、把结算后台本身开放给客户：不做——本轮没有提出，且会显著扩大权限面。
- 定时 / 邮件 / 异步大文件任务：后续——没有任何证据表明客户要的是周期交付（见确认清单 E1）。
- 结算金额计算口径与对账差异的核查：不做——那是另一个问题。如果客户的真实诉求是「金额算错了」，应另起一份 spec，导出只是被当成了手段。

## 反向推演
- AC 全过后原问题仍可能出现的情形：
  1. 客户要的字段不在导出物里 → 字段范围没有任何来源，据此补不出 AC；转为确认清单 E3 与未决 Q1。
  2. 客户要的是「每月自动发一份」而不是「手动导一次」 → 列入范围外（后续）。
  3. 真实痛点是金额算错、导出只是手段 → 列入范围外，建议另起一份 spec。
  4. 数据落在正确的租户范围内、但被交给了不该拿到的人 → 转为确认清单 E2/E4（可见范围与留痕口径）。
- 依据：上面 4 条都指向「范围未定」而不是「AC 写错」，在需求方回复前补不成 AC；没有可以回答「不会」的项。

- Q2 该租户该月有多少条记录、导出多慢可以接受？— 阻塞性能约束能否写成 AC — 需要需求方或数据回答，我不编造阈值。

- Q4 若 E1 的答案是「一次性」，这份 spec 是否还成立？— 阻塞整份 spec 的适用范围 — 需要需求方。
