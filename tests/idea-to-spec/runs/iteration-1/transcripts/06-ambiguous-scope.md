【收敛 第 1 轮】

当前理解：业务前台（React + TS 桩仓库）里各页面对同一类信息各写各的呈现方式，你希望它们统一；但"格式"指什么、统一成哪一种，都还没有定论。

已取证（不用你回答，先说清楚我看到的事实）：

仓库里只有 2 个页面，它们**共用同一个工具文件但各调各的函数**：

- `src/pages/OrderDetail.tsx:3` → 调 `toIso` → 显示 `2026-03-05`
- `src/pages/CustomerDetail.tsx:3` → 调 `toSlashed` → 显示 `3/5/2026`
- 两个函数都在 `src/utils/date.ts:2-3`（`toISOString().slice(0,10)`）与 `src/utils/date.ts:5-6`（`toLocaleDateString("en-US")`）

而且 `toSlashed` 不是"另一种风格"这么轻——**它会算错日期**。我按两个函数的源码在 TZ=Asia/Shanghai 下实测：

```text
2026-03-05T23:30:00Z  OrderDetail="2026-03-05"   CustomerDetail="3/6/2026"   ← 同一个时刻，差一天
2026-03-05T00:30:00Z  OrderDetail="2026-03-05"   CustomerDetail="3/5/2026"
2026-01-09T12:00:00Z  OrderDetail="2026-01-09"   CustomerDetail="1/9/2026"
```

（`toIso` 用 UTC，`toLocaleDateString` 用本地时区，跨零点就分叉。）

另外，我**全仓 grep 不到任何 CSS / className / style**（连 `index.css`、组件库都没有）。所以你说的"乱七八糟"如果是**视觉排版**（字号、间距、对齐、卡片样式），那不是"统一"能解决的——现有代码里根本没有样式可统一，那是一份全新的样式基建，是另一个需求。

本轮请逐条选择（**要 / 不要 / 以后 / 改成…**）。E1、E2 是两条不同的路，可以都选，也可以只选一条——如果两者都要，请你排一下先后，我会建议拆成两份 spec：

- **E1（日期/数值格式）**：账号下的订单，下单时间 2026-03-05 23:30(北京时间)。用户从订单列表进「订单详情」看到 `2026-03-05`，进「客户详情」看到该客户的注册时间 `3/6/2026`。→ 系统两个页面显示同一种写法，且都等于「2026-03-05」。

- **E2（视觉排版）**：用户在「订单详情」和「客户详情」之间来回切。→ 两页的标题字号、区块间距、字段对齐方式一致，页面主体左右留白相同。**注意：这条目前是零样式基线，等于新建一套样式规范，工作量与 E1 不是一个量级。**

- **E3（反例 · 请明确否决或保留）**：订单详情页的**金额**字段，用户确认本次**不**动——它现在显示 `¥1,200.00`，统一日期格式不应改到它。→ 系统金额写法保持不变。

- **E4（边界 · 数据来源）**：老数据里有一条订单的 `createdAt` 是空值 / 非法值。→ 页面显示 `—`，且不白屏、不抛错。

还需回答（3 个，按阻塞程度排序）：

- **Q1：这里"格式"你实际指的是什么？** 是上面的 E1（同一类信息的写法不统一）、E2（视觉排版不统一），还是我漏掉了别的（比如字段顺序、中英混排、金额千分位、手机号/地址脱敏写法）？—— 这决定了要不要拆成两份 spec。

- **Q2：如果要统一，**谁**说了算？** 我看不到任何设计稿、design token、组件库或既有规范文件（`AGENTS.md` 只有一句话：React + TypeScript）。仓库里只有 2 个页面、15 行代码，所以"统一"只能靠外面定一个基准。请给一个方向：以现有 `OrderDetail` 的 ISO 写法为准（我建议这个，因为它同时修掉了上面那个差一天的 bug）／以某个设计稿为准（请给图）／以某条产品规则为准（请给）／还是"你先把方案提出来我再拍"。

- **Q3：你是提需求的人，还是替别人转达的？** 如果 "看着难受" 是别人（产品/设计/客户）说的，那 E1 选哪种写法、E2 的样式基准、以及"不改金额"这类取舍，我不能替你拍板——我会把它们原样写进「需求方确认清单」让你转发，spec 状态记为 `待需求方确认`；如果这些你本人就能定，我们就可以在这一轮往下走。

（另：第 1 轮不写 spec 全文。E1/E2/E3/E4 里凡是需要你拍的值——比如最终写法到底是 `2026-03-05` 还是 `2026年3月5日`——我**不会**先替你填一个看起来合理的，你那边的选择就是唯一来源。第 2 轮我会带完整 spec 回来。）

本轮请逐条选择（要 / 不要 / 以后 / 改成…）：

  - 改成…（例如显示"未知"、或显示空串）
  - 以后（本次不处理；我在范围外写明"非法日期仍会白屏"，且不写这条 AC）

还需回答（2 条，按阻塞程度排序）：
