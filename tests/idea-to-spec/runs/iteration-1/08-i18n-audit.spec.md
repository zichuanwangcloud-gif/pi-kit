# 德语等长文案语言下控件被撑变形/裁切，且文案条目缺失时界面把内部 key 串显示给用户

> 状态：草稿　｜　更新于 2026-10-13　｜　收敛轮数 3

## 问题

**P1（长文案裁切/变形）**：使用德语界面的用户（需求方本人是其中之一）在打开登录页、看到登录按钮时，因为 `login.submit` 的德语译文比默认语言长、而按钮没有 max-width / 文本溢出处理，导致按钮被撑变形、文案被裁掉，用户看到一个「像坏了」的界面；目前靠 **<绕行方式：待补，未取证到>** 应付。[来源：需求方 E1 原话「德语登录页那个登录按钮，文字太长把按钮撑变形、还被裁掉了，我碰到的就是这个」；需求方 E6 选①「难看、看着像坏了，但按钮还能点，登录这件事没被挡住」；`src/components/LoginForm.tsx:4-6` 源码注释]

**P2（缺条目暴露内部串）**：使用缺少文案条目的语言的用户，在界面渲染该条目时，因为缺条目没有兜底，导致界面把内部 key 串（如 `login.submit`）当文案直接显示给用户；目前靠 **<绕行方式：待补，未取证到>** 应付。[来源：需求方 E2 第④项回答「key 缺了直接把 login.submit 显示给用户那种，对，那也是界面出问题，算」]

## 目标结果

- G1 德语界面下，登录按钮的文案完整可见、按钮不变形 —— 界面不再因此显得「像坏了」。验收按呈现标准，不加功能标准。[来源：需求方 E1「这次要弄」+ E6 选①「验收你就按『文案完整可见』这类呈现标准写，不用再加功能那一条」]
- G2 文案条目缺失时，界面不再把内部 key 串显示给用户。[来源：需求方 E2 第④项确认]

## 现状

- **入口**：`src/components/LoginForm.tsx:10` —— `<button className="btn-login" onClick={onSubmit}>`，文案取自 `t("login.submit")`（`src/components/LoginForm.tsx:11`）。
- **生效实现（渲染层）**：**不存在**。`src/components/LoginForm.tsx:1` 的 `import { t } from "../i18n";` 指向仓库中不存在的模块；`find src/i18n -type f` → 0 个文件（空目录）。
- **已观察到的呈现缺陷（来自源码注释，不是需求方原话）**：`src/components/LoginForm.tsx:4-6` 记载「按钮没有 max-width / 文本溢出处理，德语等长文案语言下按钮会被撑变形、文字被裁掉」。
- **P2 的当前行为**：无代码取证 —— 缺条目时输出内部 key 串的行为本应发生在 `t()` 实现里，而该实现不存在于本仓。现有依据仅为需求方在界面上的观察（E2④），标注为「用户观察，未经代码取证」。
- **复现：未复现。** `cd repo && find . -type f` 实测全仓仅 2 个文件：`./AGENTS.md`、`./src/components/LoginForm.tsx`；无 `package.json` / `tsconfig.json` / 构建配置 / 任何样式文件 / 任何语言资源文件（`find . -name "package.json" -o -name "tsconfig.json" -o -name "*.css" -o -name "*.scss"` → 0；`grep -rn "t(" .` 仅命中 `src/components/LoginForm.tsx:11`）。无依赖即无法起本地页面，故未复现，仅有源码级证据。
- **触发条件**：P1 —— 德语界面 + 登录按钮（需求方 E1 确认）。P2 —— 某语言缺少文案条目时（需求方 E2④ 确认该现象成立，但未指出具体语言）。
- **取证与触发词的冲突（未解决）**：触发词称「系统现在支持好几国语言」，但本仓没有任何语言资源、没有 `t()` 实现、`src/i18n` 为空目录。该前提在本仓不成立，见 Q1。此冲突未解决前，本 spec 的「现状」与「落点」两格无法闭合。

## 候选方案

- **采用（呈现层，覆盖 AC1–AC4）**：让控件呈现尺寸不再随译文长度变化，并让超长译文完整可见。方向与 `src/components/LoginForm.tsx:4-6` 注释所指（按钮补 max-width / 文本溢出处理）一致。理由：需求方 E1/E6 确认症状与验收标准都在呈现层，且明确要求不动登录业务逻辑（E3）。
- **采用（兜底层，覆盖 AC5）**：文案条目缺失时不把内部 key 串作为可见文案输出。理由：需求方 E2④。
- **两个问题写在同一份 spec**：两者落在同一处（登录页文案的渲染与兜底），且 P2 的生效实现同样缺失，拆成两份 spec 会产生同一落点的重复条目。理由：[推断]（依据：`src/i18n` 为空目录，登录页文案与兜底同属该模块）。
- **放弃**：改默认语言、改登录业务逻辑、改 key 名 —— 需求方 E3「默认语言和登录逻辑别动」「只要别改 key 名」。
- **放弃**：改译文内容/译文质量 —— 需求方 E3「那不是我能定的，得问本地化团队」。
- **放弃（本次不追求）**：字面诉求「把多语言的问题都解决一下」的整体范围 —— 已由 E4=② 收敛为「文案变长把控件撑变形/裁切」这一类 + P2 缺条目兜底；日期数字格式、复数、RTL 不在内（E2 ①②③）。
