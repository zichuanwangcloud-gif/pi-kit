# 运营后台订单列表首屏打开过久

> 状态：待需求方确认　｜　更新于 2026-10-13　｜　收敛轮数 3

## 问题

运营后台的使用者在工作时段打开订单列表第 1 页时，因为生效查询
`SELECT * FROM orders WHERE tenant_id = $1 ORDER BY created_at DESC LIMIT 20 OFFSET $2`
对 `created_at` 没有复合索引，并发上来后退化为全表扫描（`repo/src/services/order-list.ts:3-10`），
导致首屏 20 条迟迟不出现，运营为此付出等待成本——需求方原话是「别再点一下等半天就行」。
目前没有绕行方式：仓库内 `listOrders` 没有调用方，`src/routes/` 是空目录，列表页在代码侧只有这一个实现，
没有可切换的备用入口。[来源：用户原话 + 代码取证]

## 目标结果

- G1 运营在工作时段打开订单列表第 1 页时，首屏 20 条在 2 秒内出现；任何一次超过 2 秒都视为未达成。
  [来源：需求方原话「2 秒以内我都能接受」；E4 选 a「哪次冒出来 3 秒，那就是还没弄好」]
- G2 列表对使用者呈现的内容与现在完全一致：`created_at` 倒序、每页 20 条、返回字段不变。
  [来源：需求方原话「列表看着跟现在一样」]
- G3 除首屏列表查询本身外，其它路径的耗时不变差。 [来源：需求方原话「别的地方别给我弄慢了」]
- G4（待确认）下单写入路径的耗时允许增加不超过 10ms 以内、且不被人感知。
  [来源：E5 选 a + 候选值「+10ms 以内」；阈值属例子化取值，随本次修范围决策一并复确认]

## 现状

- 入口：未找到 HTTP 入口。`repo/src/routes/` 为空目录，全仓 grep `listOrders` 只命中定义处，无调用方。
- 生效实现：`repo/src/services/order-list.ts:5-10`，
  `listOrders({tenantId, page})` 执行 `SELECT * FROM orders WHERE tenant_id = $1 ORDER BY created_at DESC LIMIT 20 OFFSET $2`，
  绑定参数 `[tenantId, (page - 1) * 20]`。
- 当前行为：代码自带注释（`order-list.ts:3-4`）写明——对 `created_at` 做范围扫描、无复合索引，
  早高峰并发上来后这条查询退化为全表扫描。
- 未复现，也取不到实测值：仓库只有 `AGENTS.md` 与 `src/services/order-list.ts` 两个文件，
  没有 package.json / tsconfig / 迁移或索引定义，`../db` 模块不存在，服务起不来。
  因此首屏真实延迟、最大租户的 `orders` 行数量级、工作时段并发，均无来源可查。
- 未做代码取证的部分：无（有仓库即已取证；缺的是运行期数据，属未决问题 Q1）。

## 候选方案

- 采用（待 E7 确认后才定为采用）：给 `orders` 表加复合索引 `(tenant_id, created_at)`，
  使排序走索引、与总条数解耦。理由：`order-list.ts:3-4` 的注释指出现状退化的原因是缺复合索引；
  该做法不改查询谓词与结果集（`WHERE tenant_id = $1`、`ORDER BY created_at DESC` 均不变），
  与 G2 的行为保持诉求一致。
- 放弃（本次不做）：缓存 / 预计算 / 物化视图。理由：E5 选 a 已接受写入侧增加几毫秒的代价，
  说明不必为「写入一点都不变慢」引入更重的方案；E6 选 a 也把数据量增长带来的隐患排除在本次之外。

## 约束（非功能）

- 性能：首屏 ≤ 2 秒为硬性判据，非统计口径（AC1/AC2）；下单写入允许 ≤ +10ms（AC4，待 E7 复确认）。
- 数据规模与并发：本次按「现有生产数据量」验收；数值未定（Q1），是本 spec 唯一的阈值来源缺口。
- 权限：与本改动不相关。理由：加索引不改变查询谓词 `WHERE tenant_id = $1`，可见行集不变。
  如对方认为跨租户可见性也要在本次验收，需补一条负向 AC（已在确认清单里问过，尚未答复）。
- 兼容：不相关——无既有索引或 schema 定义文件可被本次改动破坏，仓库内无 DDL 可改。
- 可观测性：未做代码取证——仓库内无任何监控、指标或日志文件，无法确定该查询当前以何指标暴露。
  上线后的观察方式以「有效性信号」为准。
- 数据迁移：本次不新增或变更数据结构（见范围外；若确认清单中「是否动数据库结构」的答复为「可以动」，
  则本约束需改为「新增索引需可在生产在线执行」）。
