# 同一时刻在两个页面被读成两个日期：统一日期的显示写法

> 状态：待需求方确认　｜　更新于 2026-10-13　｜　收敛轮数 3

## 问题
在同一个账号下核对订单与客户时间信息的人（含本次提需求的设计）在「订单详情」与「客户详情」之间来回核对同一类时间信息时，因为两个页面对日期各写各的呈现方式（`2026-03-05` 与 `3/5/2026`），而且两者取的日期来源还不一样（一个按 UTC、一个按本地时区），导致**同一时刻在两个页面被读成两个不同的日期**（实测同一时刻差一天：`2026-03-05T23:30:00Z` 在一页是 `2026-03-05`、在另一页是 `3/6/2026`），读者无法判断以哪个为准；目前靠回头再核一遍、人工换算应付。

[来源：用户原话「这几个页面的格式乱七八糟的，统一一下吧，看着难受」＋第 2 轮澄清「就是日期，几个页面的日期写法不一样，看着乱就是乱在这儿——不是排版，也不是字段顺序、中英混排那些，你别往外扩」；差一天的实测输出见「现状」]

## 目标结果
- G1 同一笔订单（以及它的客户）的时间信息，在「订单详情」与「客户详情」两处显示为**逐字相同**的日期字符串，且形式与「订单详情」页现状一致（`2026-03-05`）。[来源：用户确认——第 2 轮「统一成哪种：就照订单详情页现在那个写法来，2026-03-05 这样的」]

## 现状
（已做代码取证。仓库 `/tmp/idea-eval/r20261013T114913Z-2736548/06-ambiguous-scope/repo`，全仓 4 个文件、18 行，无 `package.json`。）

- 入口：全部是现有代码，本次不新增能力。两个页面各调一个函数：
  - `src/pages/OrderDetail.tsx:1,3` → `toIso(order.createdAt)` → 显示 `2026-03-05`
  - `src/pages/CustomerDetail.tsx:1,3` → `toSlashed(customer.createdAt)` → 显示 `3/5/2026`
- 生效实现：
  - `src/utils/date.ts:2-3`＝`d.toISOString().slice(0, 10)`（按 **UTC** 取日）
  - `src/utils/date.ts:5-6`＝`d.toLocaleDateString("en-US")`（按**本地时区**取日，写法 `M/D/YYYY`）
  - 该文件首行注释即写明：「项目里没有统一的日期格式化函数，各页面各写各的。」
- 复现（`TZ=Asia/Shanghai node`，直接取两个函数的源码执行）：

  | 输入（同一时刻） | `toIso`（订单详情页） | `toSlashed`（客户详情页） |
  |---|---|---|
  | `2026-03-05T23:30:00Z` | `2026-03-05` | `3/6/2026` ← 与左列差一天 |
  | `2026-03-05T00:30:00Z` | `2026-03-05` | `3/5/2026` |
  | `2026-03-04T16:30:00Z` | `2026-03-04` | `3/5/2026` ← 与左列差一天 |
  | `2026-01-09T12:00:00Z` | `2026-01-09` | `1/9/2026` |

- 空值 / 非法值实测（同样 `TZ=Asia/Shanghai`，取两个函数源码）：

  | `createdAt` 传入 | `toIso`（订单详情页） | `toSlashed`（客户详情页） |
  |---|---|---|
  | `new Date("")`（Invalid Date） | 抛 `RangeError: Invalid time value` | 不抛错，渲染出 `Invalid Date` 字样 |
  | `new Date(undefined)`（Invalid Date） | 抛 `RangeError: Invalid time value` | 不抛错，渲染出 `Invalid Date` 字样 |
  | `new Date(null)` | `1970-01-01` | `1/1/1970`（不报错，静默变成 1970 年） |

    即「空值」其实是两种：`null` 会静默显示成 1970 年；`""` / `undefined` 会让订单详情页抛错（React 渲染中即整页白屏），而客户详情页只是显示异常字样——**两页行为不同**。
- 影响面（grep 全仓，`toIso`/`toSlashed`/`toLocale`/`Intl`/`dayjs`/`moment`/`date-fns`）：`toIso` 仅被 `OrderDetail.tsx:3` 调用，`toSlashed` 仅被 `CustomerDetail.tsx:3` 调用，**没有第三个调用点**；`src/pages/` 下只有 2 个页面文件。
- 与范围外相关的取证：全仓 grep `className` / `style` / `.css` / `.scss` / `tailwind` **0 命中**，无 `index.html`、无任何样式文件与组件库；grep `¥` / `amount` / `price` / `currency` **0 命中**（没有金额字段可改）。`AGENTS.md` 全文只有一句：「React + TypeScript」。
- 未取证项：本仓库无构建配置、跑不起页面，因此以上结论是按两个函数的源码在 Node 下实测得出的；页面级验证需要在宿主工程里进行。

## 候选方案
- 采用：在 `src/utils/date.ts` 收敛为**一个**日期格式化出口（保留 `toIso` 的实现），把 `src/pages/CustomerDetail.tsx:1,3` 改为调用它。理由：与用户选定的基准（订单详情页现状写法 `2026-03-05`）逐字一致；是让「两页同串」成立的最小改动；不新增文件、不新增依赖。
- 放弃：以 `toSlashed` 为准（改为 `3/5/2026`）→ 会改动「订单详情」页现状，与用户选定基准相反。
- 放弃：引入 date-fns / dayjs 等日期库 → 仓库当前无 `package.json` 与依赖声明，属新增依赖，超出本次范围且用户未要求。
- 放弃：改成按浏览器本地时区取日 → 用户第 3 轮明确「时区那个不在这次范围内，就按现在这样来，别动它」。
