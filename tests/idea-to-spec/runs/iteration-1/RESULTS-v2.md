评委可信，本轮分数可用。

## 核心结论：v1 把模拟器的错记在了 skill 头上

| 指标 | v1 | v2 |
|---|---|---|
| precision | 0.685 | **0.932** |
| recall | 0.695 | 0.671 |
| 评委间 precision 极差 | 0.156 | **0.058** |
| 评委间 recall 极差 | — | 0.071 |
| skill 幻觉（中位数/用例） | 5.25（含误判） | **0.875** |
| 需求方模拟器漂移（条/用例） | 未测 | **2.5** |

**v1 报的"每条 AC 都贴权威标签"大面积是误判。** 复查原始对话：
「你按你觉得稳的做」「跟 IP 没关系」「2 秒以内我都能接受」「key 缺了直接显示 login.submit，对，算」
——**这些都是需求方 agent 亲口说的**，skill 忠实记录，v1 却判成伪造。

真实情况：**模拟器每用例平均说 2.5 条 hidden 之外的具体内容**（即兴发挥），污染了 v1 的分数。

## 真正要修的问题：召回，不是幻觉

precision 0.932 已经不差；**recall 0.671 才是短板**，且 `withheld` 在所有用例都为空——
**说明漏的是"没问"，不是"问了没答"**，责任在 skill。

### 漏问的共同形态（这是本轮最有价值的发现）

对比用例 03 里 skill 问的和没问的：

| 它问了 | 它没问 |
|---|---|
| 最大租户 `orders` 有多少行 | **什么时候慢**（9:30–10:30 早高峰） |
| 高峰时段并发多少 QPS | **影响多少人**（约 300 名运营） |
| 是否允许加复合索引 | **平时是不是也慢**（平时 1 秒内） |
| 列表排序/字段是否不变 | **有没有产生错误**（纯等待，无错误） |

**它审问代码的未知，却不审问人的体验。** 凡是可以从代码或监控查的数（行数、并发、索引），
它都追得很细；凡是只有使用者才知道的（何时慢、影响谁、有无报错），它一句没问。

用例 04 同理：问了"给自己同事还是发给外部客户"（可从上下文推），漏了"每周手工花 0.5 小时"（只有需求方知道）。

### 少数的真幻觉

- 02：问题段「目前靠人工从后台或数据库直取应付」标「用户确认」——**确认外溢**：
  需求方只认了「入口可见性」这个方向，被测方把确认扩大到整段提议，连自己猜的绕行方式一起变成「已确认」。
- 06：范围外「手机号／地址脱敏写法」——仓库无此字段，hidden 未提，凭空引入。
- 08：AC5 从「德语登录页」扩成「任意语言任意条目的通用禁令」，标为需求方确认。

## 结论

1. **测量已可靠**：校准 3/3 全中、评委间极差从 0.156 降到 0.058。
2. **v1 的主要结论是错的**：那不是"贴标签幻觉"，是模拟器漂移 + 评委看不到对话。
3. **迭代 2 的方向随之改变**：不修"来源标注"（现状 0.93 已好），改**提问覆盖度**——
   尤其是"只有使用者才知道的事实"这一类。
