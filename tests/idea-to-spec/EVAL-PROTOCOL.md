# 评测协议

每次评测跑一个用例：两个角色 agent 在各自独立上下文里交互，第三个 agent 只看产物打分。

```text
public.md ──► 被测 agent（加载 idea-to-spec，只看 public）
                    │  提问
                    ▼
             需求方 agent（持有 hidden.md，只答不问）
                    │  回答
                    ▼
              产物 spec.md ──► 机器 linter + 评委 agent ──► 分数
```

**隔离要求**：被测 agent 的上下文里绝不能出现 `hidden.md`。它只能通过向需求方 agent 提问来获取信息。
`public.md` 与 `hidden.md` 分文件存放，就是为了让这一点可以被机械保证。若被测 agent 直接读取
`hidden.md`，该次运行作废。

## 角色一：被测 agent

- 输入：`cases/<slug>/public.md` 的 `trigger` 原文，加上「加载 `idea-to-spec` 并按其流程执行」。
- 禁止：读取 `hidden.md`、任何 `fixtures/` 下的文件、评测目录；禁止查看 git 历史或已被删除的用例原文。
- 提问方式：每次向需求方 agent 提出一组问题（遵循 skill 自身的每轮 ≤3 问约束）。
- 终止：按 skill 的规则产出 spec，或在 skill 判定停止/探查时停止。
- 交付：spec 全文（写成文件），以及本次交互中它问过的全部问题清单。

## 角色二：需求方 agent

- 输入：`cases/<slug>/hidden.md` 全文。
- 身份：就是 hidden 里的「需求方立场」。对话者是谁，由 hidden 决定。
- 规则：
  - **只回答被问到的问题。** 不主动补充、不提示「你还没问 X」、不列举事实清单。
  - 抽象提问按 hidden 里「可问性」栏的说明回应（例如业务取舍类问题只说「越快越好」）。
  - 演到需求方该有的情绪（急、犹豫、不懂技术），但不因此泄露未知信息。
  - 当被问到「未知」类事实时，回答「我也不知道」，除非 hidden 另有说明。
  - 若被问到「只对特定角色」类事实，回答「这个我定不了，得问 X」。
  - 不出戏：不引用 Markdown 格式、不提到 fixture、不提到自己在扮演角色。

## 角色三：评委 agent

只拿三样东西：`hidden.md`、产出的 spec、linter 输出。**看不到对话过程**——对话过程会让评委被措辞说服。

## 评分口径

四项指标 + 一项机器分，权重固定如下，评测前不得调整：

| 指标 | 权重 | 定义 |
|---|---|---|
| **召回率 recall** | 30% | hidden 的「事实」中，被问出来并正确写进 spec 的比例。遗漏每个扣分 |
| **准确率 precision** | 30% | spec 里的每条断言，是否都能追溯到「用户/需求方明确确认」「代码取证」或标了 `[推断]`。无法追溯 = 幻觉，重罚 |
| **边界 scope** | 20% | 「范围外」是否与 hidden 一致；是否把未知转成探查/未决而不是硬编 AC |
| **可验收性** | 20% | AC 是否为 EARS 句式、带具体例子、无不可判定词汇 |
| **linter score** | 参考项 | 机器分，不计入上面四项权重，但任何 error 必须在报告里单列 |

**幻觉判定**：凡是 spec 中出现、且无法对应到 hidden 任一事实或用户确认的**具体断言**
（具体数值、具体列名、具体原因、具体接口），即为幻觉。含糊表述不算幻觉，具体编造才算。

**反脆弱要求**：只惩罚漏项会让 skill 学会把一切塞进 `[推断]`；只惩罚幻觉会让 skill 学会什么都不写。
所以两项都必须达标，且 `[推断]` 标注本身不算达标——推断项超过 AC 总数 1/3 时，准确率封顶 0.6。

## 每轮迭代的停止条件

连续两轮「四项加权总分」变化幅度 < 2%，且没有新增 error 级别的 linter 问题，即视为稳定，停止。
